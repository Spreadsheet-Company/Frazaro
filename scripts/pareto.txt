# pareto.vocabulary — the beta coverage backlog

**What this file is.** A specification corpus of ~240 single-operation English
sentences chosen to cover the great majority of what real spreadsheet SOPs
actually do, with the VBA/COM operation each one must reach. It is the input to
the wiring work, not the output of it.

**What this file is NOT: a loadable `.vocab` file.** Two project laws forbid
that, and both are load-bearing:

1. **Pins and templates come from verified emission.** Every template below
   would be a blind guess at emitted VBA. The wiring chat must write each
   template, run it, read the actual bytes, and only then pin them.
2. **A rule without proofs cannot ship.** Each rule needs `test:` (and where the
   surface has a refusal, `fail:`) lines, and those must be produced against a
   running machine or the loader will reject the phrasebook.

So: take a section at a time, design the rules, build any Tier-2 helper it
needs, write the proofs from real output, and ship it as a pass with predicted
golden shapes. This file supplies the *surfaces* and the *targets* — the two
things that are safe to decide away from the machine.

---

## How to read an entry

```
  id                    | English surface                                   | target operation
  set-row-height        | Set height of row {r:expr} to {n:expr}.           | .RowHeight = n
```

**Slot types are the seven the corpus already uses**: `cell`, `range`, `column`,
`sheet`, `text`, `var`, `expr`. Numbers ride `{n:expr}`. Where a section wants a
*new* slot type (a file path, a pivot field list), it says so in its preamble —
those are grammar decisions, not rule decisions, and they belong on the roadmap
before the rules that need them.

**Markers**

| | meaning |
|---|---|
| `!` | needs a **Tier-2 runtime helper** — the COM sequence is too long or too stateful to inline |
| `~` | needs a **grammar feature first** (G6 list slots, G7 defaults, G8 number words) |
| `^` | should be wrapped in an L13 bracket (`with-no-alerts`, `with-screen-off`) — Excel prompts or flickers otherwise |
| `?` | **semantic decision required** before design: note in the entry says what |

**Priorities.** `P0` = a beta without it looks unfinished; appears in most SOPs.
`P1` = common, expected by month two. `P2` = real but narrower. Ship P0 across
all sections before any P1 — breadth beats depth for a corpus whose purpose is
to stop users hitting walls.

## 1. Selection, references, and naming — P0

*No new plumbing. Mostly thin wrappers over existing range resolution.*

```
select-range          | Select range {r:range}.                             | .Select
select-cell           | Select cell {r:cell}.                               | .Select
name-range            | Name range {r:range} as {n:text}.                   | Names.Add Name:=n, RefersTo:=rng
delete-name           | Remove the name {n:text}.                           | Names(n).Delete
goto-name             | Go to {n:text}.                                     | Range(n).Select
last-column           | Set {v:var} to last filled column of row {r:expr}.  | .End(xlToLeft).Column

used-range            | Set {v:var} to the used range.                      | .UsedRange
row-count             | Set {v:var} to number of rows in {r:range}.         | .Rows.Count
column-count          | Set {v:var} to number of columns in {r:range}.      | .Columns.Count
is-empty-range        | If range {r:range} is empty, ...                    | WorksheetFunction.CountA(rng) = 0
```

## 10. Pivot tables — P0 for beta credibility

*Owner-flagged as a headline gap. Every entry is `!`: pivots are a cache plus a
table plus field orientation, and the VLA must stay readable. Recommended
design: one Tier-2 helper per verb, and a `{f:field-list}` slot from G6 so that
"with rows of A, B and columns of C" is one sentence rather than four.*

```
pivot-create      !~  | Create a pivot table from {r:range} at {b:cell} called {n:text}. | PivotCaches.Create + CreatePivotTable
pivot-rows        !~  | Add rows of {f:expr} to pivot {n:text}.               | .PivotFields(f).Orientation = xlRowField
pivot-columns     !~  | Add columns of {f:expr} to pivot {n:text}.            | xlColumnField
pivot-filters     !~  | Add filters of {f:expr} to pivot {n:text}.            | xlPageField
pivot-values-sum  !   | Add {f:text} to pivot {n:text} as a sum.              | AddDataField(..., xlSum)
pivot-values-count!   | Add {f:text} to pivot {n:text} as a count.            | xlCount
pivot-values-avg  !   | Add {f:text} to pivot {n:text} as an average.         | xlAverage
pivot-full        !~  | Create pivot from {r:range} with rows of {a:expr} and columns of {b:expr} and values of {c:expr}. | the composite sentence the owner asked for; build it from the parts above
pivot-refresh     !   | Refresh pivot {n:text}.                                | .RefreshTable
pivot-refresh-all !   | Refresh every pivot table.                             | loop PivotTables
pivot-delete      !^  | Delete pivot {n:text}.                                 | .TableRange2.Clear
pivot-layout      !?  | Show pivot {n:text} in tabular form.                   | .RowAxisLayout xlTabularRow — decide which layout names to expose
pivot-collapse    !   | Collapse pivot {n:text}.                               | .PivotFields(...).ShowDetail = False
```

## Sequencing recommendation

The corpus above is roughly 240 entries. Do **not** work down it in order — work
in the order that removes walls fastest:

1. **§5 + §6 + §1 + §2 (formatting, number formats, references, structure).**
   Almost pure Tier-1, no new plumbing, and it is where a beta looks thin or
   looks finished. Probably 60+ rules in a handful of passes.
2. **§3 + §4 (copy/paste/clear).** Highest per-rule value in real SOPs.
3. **§20 (row loops) + §8 (sort/filter).** These two turn the grammar from "cell
   operations" into "table operations," which is the owner's stated gap.
4. **§14 + §15 (sheets, files).** The G-TABS and G-FILES passes already on the
   Alpha 6 roadmap; §15 needs the `{p:path}` slot decision first.
5. **§11 + §12 + §13 (formulas, text, find/replace).**
6. **§10 (pivots).** Deliberately after G6 list slots exist — the composite
   sentence is unwritable without them, and building it twice is a waste.
7. **§7, §9, §16–§19, §21, §22** as demand dictates; the sentence-gap issues
   from real users should reorder this tail, not this file.

**Grammar prerequisites worth extracting before the rules that need them:**
`{p:path}` slots (reuse the G12 quoted-name decision), G6 list slots (pivot
fields, multi-column sorts, dropdown items), G7 defaults (nearly every optional
`on sheet {s:sheet}` clause), G8 number words ("Insert three rows"), and a
decision on whether every range verb accepts a bare cell (it should — `Make cell
A1 bold` and `Make A1:C9 bold` want one rule, not two).

**Estimated shape of the finished corpus:** ~340 rules total (102 today + ~240
here), which on the session's observed density is 700–900 `test:` proofs. That
is a large but very mechanical body of work — and every one of those proofs is
re-run at every load, which is exactly the property that makes a corpus this
size safe to own.
