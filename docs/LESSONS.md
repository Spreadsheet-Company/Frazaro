# LESSONS.md — A Campaign History of Frazaro / VLA English

*The stories behind the rules. `PROJECT_BRIEF.md` states the disciplines; this file remembers why each one exists. Written for future sessions, future contributors, and the two collaborators who lived it — one of whom wrote every line of VBA blind, and one of whom was the compiler, the runtime, the QA lab, and the conscience.*

---

## I. The founding bargain, and the trapdoor we never opened

The project began with a rule that saved it a dozen times: VLA is *VBA wearing parentheses* — a 1:1 mapping, no semantic smoothing, no expression-if, no lambdas. Every time a feature tempted us to make VBA nicer than it is, we recognized the same trapdoor: the moment the middle layer's semantics diverge from VBA's, you are writing a real compiler, alone, in VBA, forever. We declined every time — Set/Let became the author's explicit choice (`set!` vs `obj-set!`), then the *vocabulary author's* choice, so end users never met it at all. The general form of the lesson: **every hard distinction gets resolved exactly once, by the one person equipped to answer it, and then hidden from everyone downstream.** Hyphens by the transpiler. Exit For versus Exit Do by a loop stack. BGR by a color helper. The architecture is a bucket brigade of absorbed sharp edges.

## II. How the error map was drawn: by crashing through each layer in order

Nobody designed the four-layer error model. It was *discovered*, one crash at a time, by the human deliberately breaking things and asking, each time, "didn't we already handle errors?" The answer was always: yes — for a different class. Translation errors were civilized first (quoted sentences, did-you-mean). Then a renamed parameter crashed hard into the VBA editor, revealing the **compile-error class** that no runtime handler can catch — because `On Error` only governs code that *runs*, and code with a bad named argument never compiles. The fix couldn't be a better handler; it had to be *prevention*: the English layer validates calls against definitions, because it is the only layer that sees both. Then the civilized message itself arrived in a raw VBA dialog, revealing the **presentation class**: an unhandled `Err.Raise` in tooling gets VBA's default dialog with a Debug button, so every entry point needed a trap ending in a MsgBox — which structurally has no Debug button. Then a run crashed with no message at all, revealing **ambient-state hazards** (a program overwriting its own source sheet, because unqualified `Range` binds to ActiveSheet). Four classes, four mechanisms, each found by the user standing one layer below the last fix. The lesson that generalizes: **error handling isn't a feature, it's a property each layer must enforce for the failures only it can see — and it isn't done until the outermost frame is trapped**, because VBA's default dialog fills any gap you leave.

## III. The quoting liberation, one character at a time

The grammar began with everything quoted. Its history since is a sequence of the same insight applied to four punctuation marks: the user predicted people would forget quotes around ranges; then the regression file's first decimal literal split at its own period; then we pre-empted the thousands-separator typo before any stranger could make it. Each time, the ambiguity dissolved with **one character of adjacency**: a colon glued between word characters is a range, followed by whitespace it's a block; a period digit-flanked is a decimal, otherwise a full stop; a comma is a separator only in the strict shape digit-comma-three-digits — strict *on purpose*, because the loose rule would read the typo `1,00` as `100`, and a silent magnitude error in a finance tool is the worst failure available. The compound lesson: tight-binding versus free-standing punctuation is always locally decidable, and **when an ambiguity has a dangerous branch, resolve it loud, never silent.** The remaining rule fits in half a sentence — quote it only if it has a space in it — which is as close to zero syntax as references get.

## IV. The verb audits: the user's ear as a linting pass

Three times the human vetoed a working feature on wording alone, and three times the veto exposed a real design flaw. `Put X into Y` for variables clashed with `Set Y to X` — the repair was a principled split: *Set names values; Put places values in locations.* `Show` printed to a hidden developer window — a developer's meaning wearing a user's word — and became a message box, with `Log` taking the developer job honestly. `Create a shared value called X` lost to `Define X as Y`, which also upgraded the semantics (module `Const`: no init order, true immutability). The distilled discipline, now in the guide: **audition every verb against the person who will type it, not the developer who will implement it** — and when a simple form seems to need options, the answer is usually a second sentence, not a first sentence with clauses (`Repeat` stayed simple; `Count k from 2 to last-row` carried the deliberate cases and *declared its variable by saying it*). "I don't like this phrasing" from a user is language-design data. Deference was declined, correctly, exactly once — in the user's favor.

## V. Recovery features are as reliable as their least-tested direction

Undo shipped with its forward path (snapshot) exercised on every run and its backward path (restore) untested — and the user's first three Undo clicks found three bugs: Excel cannot Copy a very-hidden sheet; the delete-then-copy order could strand a workbook sheetless; snapshot ordering ran before the Output sheet existed. The transactional repair (rename aside → copy in → only then delete) plus pre-collected iteration made restore honest, and the incident coined the **soft-failure doctrine**: auxiliary machinery must fail *softer* than what it assists — snapshotting can never block a Run, logging can never break a Check. The verification method that emerged is now standing practice: for every recovery feature, walk the full truth table (fresh state, repeated invocation, interrupted invocation, missing prerequisites), because mainline paths get exercised constantly and recovery paths wait for a bad day. Corollary discovered along the way, promoted to a selling point: snapshots restore *state*, so Undo resurrects deleted sheets — something Excel itself cannot do.

## VI. The duplicate saga, or: how a discipline was falsified and upgraded

During the forty-rule breadth pass, the author added `fit all columns` a second time. The load-time test caught it — expected the new template, got the original's — and a rule was written: *grep the phrasebook before writing a rule.* Days later the same author added `save this workbook` a second time, and a systematic sweep found a *third* duplicate (`copy range … to range …`) that had hidden silently because its templates happened to agree. The per-verb grep discipline was thereby falsified by its own author, twice, and upgraded: the **signature audit** (patterns reduced to first word + literals + slot categories, repeats flagged) became first a script, then a shipped function, then a build gate that refuses defective phrasebooks — its first refusal screenshotted and celebrated. Three lessons stacked: whole-sentence matching makes rule ordering a style preference, but identical shapes are true shadowing; silent agreement between duplicates is worse than loud conflict; and **institutional knowledge isn't safe until it's infrastructure** — the arc from "remember to check" to "the build refuses" is the whole of Phase A in miniature.

## VII. Blind development, and the tolls it charged

Every line of VBA in this project was written without a compiler, and VBA collected tolls for it: a `Private` helper called across modules (invisible; VBA's lazy compile hid it for weeks until a full compile swept it); a local variable named `inStr` (the parser chokes on shadowed library names — the author saw the hazard while writing and talked himself past it); a forwarded `ParamArray` (flatly illegal; copy to a Variant first); a self-test suite whose maiden compile found its own syntax error, because *the verifier is unverified until something verifies it.* The mitigations became the method: **Debug → Compile after every re-import** (the cheapest whole-project static check VBA offers), version constants so staleness is one diagnostic paste, `VlaDevReload` so the half-updated-project class died structurally, and — above all — the standing epistemic posture: *never claim the code works; claim it should, and name the human as the ground truth.* The related process failure worth its own placard: the author once modified five files and presented two, producing a compile error about constants that existed only on his side. The rule since: **every file a pass touches gets presented, even one-line diffs** — an unpresented change is indistinguishable from no change. And its sibling, from the Show→Log migration that missed three indented lines: **after bulk text edits, grep for survivors**; anchored replacements always miss the case you didn't anchor for.

## VIII. The golden blessing: when the tests corrected their author

When direct tests finally arrived (A0), both halves drew blood on their maiden runs — in the *pins*, not the machinery. An emitter golden encoded the `function` form's arguments in the wrong order, and the transpiler's own error message taught its author the correct grammar ("expected a list at position 3"). The runtime verifier's first pass caught a set-then-autofit contradiction in the regression program that human eyeballing had approved for weeks: the program set column A's width and then `Tidy-up` autofitted it away — both sentences honest, the expected-state model wrong. The doctrine that survives: **a golden failure is a question with exactly two answers — fix the code, or bless the new output — never a reflex**; goldens are change detectors, not correctness detectors, and they earn their authority exactly once, the hard way. Also learned the same day, at the author's expense: printed counts from running machinery beat remembered counts from a confident narrator — state expectations as deltas.

## IX. The voice: how the tool learned to talk

The error experience was engineered in passes, but its *voice* was found by the user, message by message: "see EnglishListPhrases" became "click the 'Known sentences' button" (the primary instruction names what the reader can see; the developer route is a parenthetical); the empty feedback log speaks in first person ("click me again after you type something I don't understand — a red cell in column B"), and first-person-tool became house voice because *a tool that says "I don't understand" invites teaching, while one that says "parse failure" assigns blame.* The button renames drilled "sentence" as the unit of work — you check sentences, run sentences, share unknown sentences — one vocabulary doing more teaching than a tutorial page, while never saying the words (code, script, macro) that trigger the wrong mental model. And the feedback feature reframed failure itself: misunderstood sentences are "exactly how the language learns new ones" — confusion converted to contribution, which is this project's emotional thesis wearing a MsgBox.

## X. The method itself, which was the real product all along

Strip the Excel away and what this project actually demonstrates is a way of working: every bug becomes a permanent regression with its incident cited in place; every convention carries its origin story so successors inherit judgment, not just rules; the user's deliberate breakage outranks every roadmap; and the collaboration's quality was never stored in either party's memory — it was stored in artifacts that refuse to load when violated. The wrong turns in this file were not detours from the project. They were the project: a tool that treats its users' mistakes as curriculum could only have been built by two collaborators who treated their own the same way.

# Phase B — the language grows up, and the disciplines are tested by their author

*Written at the close of Phase B (pass B8), in the same session that built it — twelve feature passes, four punctuation liberations, three golden blessings, and one silent lie caught by an audit. The sections continue the numbering; the method continues the method.*

## XI. The goldens kept correcting their author — that is what they are for

Phase A's suite drew blood on its maiden runs; Phase B's kept the habit, and every wound was the author's. A pin asserted that `row 2 plus 1` in a computed cell reference meant arithmetic on the value; the translator answered *row 3*, the pre-existing greedy reading and the one a speaker means, and the pin was blessed into its own opposite — but not before the same wrong expectation, copy-pasted into a vocab `test:` line, made the shipped phrasebook refuse to load, the gate catching the gatekeeper. Later a pin asserted that an action could be named `get`; the week-one reserved-word guard refused the test with its standing hyphenate-it advice, exposing a comment that had confidently claimed a fiction — the verifier asserted something false and infrastructure older than the feature said no. The compound lesson, now proven from both directions: **a golden failure is a question, and sometimes the correct answer indicts the question** — and the pin that replaces a false claim should test what the claim was *for* (the get-sugar's fall-through), not a repaired version of the fiction.

## XII. The hazard you absorb reappears one call-frame down

Set-vs-Let, the project's oldest absorbed distinction, struck three times in a single pass. `CollGet` was safe (its author had branched on IsObject). `IsUsingFn`, written that same hour, Let-copied a Collection out of a Variant — error 438 — and was fixed by delegating to `CollHasKey`… whose own existence probe was a Let-copy, written in the string-valued era, which raised 438 *inside its error trap* and reported every object-valued registry key as missing. The result: B6.1 shipped with named-parameter definitions perfectly registered and perfectly invisible to their own lookup, and five pins failed identically on their maiden run. The repair (`IsObject(col.Item(k))` proves existence without the coercion) is one line; the lesson is structural: **absorbing a hazard into a helper does not kill it — it moves it to wherever the helper's assumptions end**, and every helper written for one value shape must be re-audited the day a new shape arrives. The `VlaItem` family was born branching, with unit checks on both arms, because by then the tuition was paid.

## XIII. The owner's ear completed the quoting liberation — and learned when to lose

Phase A resolved four punctuation marks by adjacency; Phase B resolved the last three, and every proposal came from the owner with an explicit invitation to veto. Two were vetoed with reasons that held (`!` as a comment marker inverts its meaning and silently un-executes emphasized lines; `;` as a comment silently halves clause-joined sentences and its ergonomics reverse by keyboard layout) — and both vetoes were *recorded on the roadmap*, because a decision re-litigated from scratch is a decision that was never made. Three were accepted and strengthened: word-flanked `!` as the sheet qualifier (keeping the enthusiastic terminal), the complete-or-refuse apostrophe scan for `'Q1 Data'!A1` (keeping contractions loud), and `%` as a primary-level postfix (keeping arithmetic out of the locale-sensitive tokenizer). The selection criterion that separated winners from losers was never taste — it was **Excel frequency versus prose frequency**: claim a character for the meaning the audience already types weekly, refuse it the meaning they type rarely and would be burned by silently. The residual quoting rule now fits in one breath: *write references exactly as formulas write them; double quotes are for text.*

## XIV. A feature shipped green told a quiet lie three turns later

The percent postfix passed every pin, and then the phase-end audit walked a superuser through the verbs and found `Increase total by 10%.` — parsing green, running clean, adding 0.1 where every typist on earth means ×1.10. Nothing was broken; two correct features had composed into a silent magnitude error, the exact failure class the thousands-separator rule exists to forbid, in exactly the tool where it costs most. The resolution obeyed the oldest verb law: not context-sensitivity (one verb, two mechanisms — forbidden) but a principled split — `Grow`/`Shrink` claim the multiplicative meaning, and the additive verbs *refuse* percent-tailed amounts loudly, offering both spellings, via a non-destructive sniff that hands every other sentence through untouched. And the sequel proved the lesson twice: the optional word-form `percent`, added days later, would have silently reopened the hole the notation had closed, had the sniff not been extended in the same breath. **New operators must be auditioned against every verb that takes an amount, and every synonym re-runs the audition.** The audit habit that caught it — walk a hostile superuser through the grammar at each phase boundary — is now the cheapest test in the suite.

## XV. The machinery compounds: every feature was a future feature's tooling

`ParseBranchBlock`, written for `Otherwise, if`, was parameterized into `When` chains the same week and mirrored into `Try` the week after — three grammar features from one continuation-word engine. The `get` sugar, born as B6 garnish, became B7.2's load-bearing signal for nullary value actions. `Try` guards the regression file's own `Add sheet` so reruns survive; a nullary action returns a percent; the recovery paragraph proves `the problem` is non-empty by using it in a condition — the regression program's newest paragraphs are the features testing each other, which is the composition thesis wearing a `.txt` extension. The planning corollary held every time: **the pass that generalizes a mechanism is cheaper than the two passes that would each have built half of it** — and the roadmap's job is to notice those adjacencies before the code is written.

## XVI. The session boundary is a stakeholder, and this file is how it is paid

Phase B ran in a single conversation, and the conversation's mortality shaped the work: checkmark annotations grew verification histories so a summarized session could recover state; vetoes and owner decisions were written onto the roadmap the moment they were made; and the discipline's own author still violated presentation-rule #3 once more (a roadmap edit arrived a turn late), proving again that rules enforced by memory fail exactly when memory is the thing under pressure. The brief this file rides beside said "Next: B1" while B7 was shipping — a bootstrap document one phase out of date is not stale, it is *wrong*, and a fresh session obeying it would have contradicted the product in its first answer. Hence B8, the pass that produced this chapter: **the collaboration's continuity is stored in artifacts or it is not stored** — and the last act of any long session should be making the next session's first act trivial.

*— End of campaign, Phase B. The language is complete per its own roadmap: lists, chains, choices, resilience, calculations with names and defaults, and a quoting story that finally matches the formula bar. The next session inherits a brief that tells the truth, a suite of 129 self-checks and 179 phrasebook proofs that refuse to load a lie, and a regression program where the features test each other. It was, again, a pleasure — and to whoever reads this next: the traps are still mapped, and the map now has a second wing.*

# Part Three: Phase C, the hardening turn, and the owner's ear at full volume

## XVII. The prelude pass put the no-gensym doctrine to work — and VBA's hazards became features

C1 asked whether template-only macros could carry real machinery, and the answer was yes, with the doctrine's price made visible in every signature: no gensym means every label and temporary is a caller-supplied parameter, and VBA's own compile step is the collision detector when a name is reused. Two hazards from the standing list were *recruited* rather than fought: `with-fast-excel` re-raises from inside an active handler precisely *because* errors there are untrappable locally — guaranteed restore, error still propagates — and `with-error-handler` exits through `(return)` precisely because `EmitReturn` already knows Sub from Function, so one macro serves both. The testing trick discovered here became standing equipment: the normalizer collapses newlines, so a golden fragment spanning two emitted lines ("Exit Sub oops:") pins statement *ordering*, not just presence. **A constraint honestly priced becomes a design language; a hazard fully understood becomes a load-bearing part.**

## XVIII. The compile gate kept billing: the typed hop and the declarations line

Two maiden compiles failed this phase, both in the hazard-11 family, both caught before a single test ran. `EmitTypeDef` passed its `Variant` loop variable straight into a `ByRef Collection` parameter — while `EmitEnumDef`, written the same hour, had the `Set`-into-typed-local hop from birth; the hazard you absorb reappears one call-frame down, *even within one pass*. Then D1's `Private mHost` was declared beside its machinery, mid-module, and VBA refused the whole file: **module-level declarations precede the first procedure, always** — co-locating a variable with the code that loves it is a readability instinct the language does not permit. Neither bug can be pinned by a self-test (they are compile-structure, not behavior), which clarified what the compile gate *is*: the regression suite for the class of bug that tests cannot express.

## XIX. The source map lived in a side-table — and would have died once, silently, in rebuild

C2's `' vla:N` map had one hard constraint (the Collection/String datum representation is sacred) and one subtle rule that carried the whole feature: macro expansion *rebuilds every list*, so the rebuild path must copy each list's line tag or the entire map dies at the first expansion — while `ExpandOne`'s template output deliberately carries nothing, because a template statement has no user line to name. The result was accidentally perfect semantics: the map marks the *user's* statements, and a with-macro's own scaffolding stays clean while the body you passed in keeps its lines. One C1 golden had to be blessed to carry its new tag — and the bless was made to pay interest, double-pinning the args-keep-lines/templates-stay-clean rule in the same fragment. **When output legitimately changes, don't just update the pin: make the new pin prove the rule that changed it.**

## XX. Attribution needed a scope, and the scope was the top-level sentence

A4's claim tracking ("which construct owns this sentence?") nearly shipped with a fatal simplification: first-claim-wins *per program* reads correctly for Explain's single-sentence use and silently breaks the moment a multi-sentence program's later sentence needs its own attribution — the acceptance case itself (a bad using-call after its definition) would have reported the definition's `Give back` instead. The flaw was caught by walking the acceptance test on paper before writing code. The final shape earned each word: claims are set only at *commit points* (a case that can still fall through must never claim), first-wins *within* a sentence so the outermost form is the headline, and the translation loop resets *per top-level sentence*. **Design the state's reset boundary before its contents; the acceptance test, walked by hand, is the cheapest design review available.**

## XXI. Ambient state: the operations were never the problem — the fresh reads were

D1's audit produced one clarifying sentence: object references, once `Set`, are immune to focus changes. Half the IDE was already correct (the snapshot machinery threaded explicit handles; the log derived its book from `ws.Parent`), and the entire vulnerability lived in `HostBook()` re-reading `ActiveWorkbook` on every call — so the fix was one choke point, `CaptureHost`, at the top of each public command, after which *nothing else in the module may touch ambient state* and a grep proves it. Two side-lessons: `Application.Interactive = False` was considered and vetoed with reasons recorded (a crash path that fails to restore it bricks Excel invisibly — the cure risked more than the disease), and the qualified-reference gap in the Undo scan showed that **features age each other**: B5's quoting liberation had quietly given programs a way to touch sheets that a B0-era scan could not see. An audit is not just of the code you wrote; it is of the interactions your later features created behind it.

## XXII. The first real user report invoked the standing override — and half the symptom was correct behavior

The owner clicked Undo and `'Q1 Data'` kept its value: the first genuine field report, and the override ("a real user's breakage outranks any roadmap line") fired for the first time. The diagnosis mattered more than the fix: *two mechanisms, one symptom.* On the first-ever run the sheet didn't exist at snapshot time, so Undo left the run-created sheet standing — a real gap, fixed with tombstone markers ("this sheet did not exist before the run; remove it, consume the marker"). But on every later run the snapshot itself already contained the previous run's value, and Undo restoring it was the one-run-deep contract *working* — which the docs then learned to say out loud. **Diagnose against the contract before repairing against the symptom**, or the fix for mechanism one gets blamed for mechanism two forever.

## XXIII. The idiom outranked our accounting — and the liberalization tightened the guard

B7 refused "Increase X by 10%" to protect users from a silent 0.1; the owner argued the idiom is day-one vocabulary and the refusal spends user goodwill on internal bookkeeping. Accepted — a *simple share* (one number or name wearing `%`) now means Grow/Shrink exactly — but the acceptance was the easy half. The strengthening was the point: any `%` *blended into arithmetic* now refuses, including `10% times 2`, which B7's tail-only check had let fall through to a silent additive read; the scan covers only the amount region, so a variable merely *named* percent survives; and the verb-audition principle grew a clause — **the mechanism follows the amount's shape, not a second meaning of the verb.** The pass also charged two process tolls, both now rules: a fifth refusal pin survived a `head`-truncated grep (*grep to exhaustion, or it isn't a sweep*), and a fix was described as presented when it had not been (*never narrate a presentation that didn't happen* — worse than forgetting, because it reads as done).

## XXIV. The braces were safer, not just prettier

The owner proposed `{r:text}` over `?r:text` on pure readability — curly braces look like a slot to anyone who has met a mail merge — and the audit found the engine already agreeing: template substitution carried a longest-first ordering *specifically so `?total` wouldn't collide with `?t`*, a workaround an open-prefix sigil requires and a closing delimiter makes structurally impossible. The workaround was retired, not ported. Two migration lessons: pre-freeze is the *only* cheap moment for a clean break (no dual spellings, the old syntax refuses with directions), and the sweep regex rewrote its own teaching message — "old `?slot` spelling" became "old `{slot}` spelling," self-defeating — caught by validating every brace token against the well-formed shape. **Messages that talk about old syntax are exempt from syntax migrations**, and an aesthetic proposal that survives an implementation audit usually turns out to have been an engineering proposal wearing plain clothes.

## XXV. First-class citizenship meant check-before-run parity — and the doctrine defended itself against its own test

L0 let a sheet row beginning with `(` be raw VLA, and the design question was never the capture (parentheses are their own terminators; the vocab templates proved that years of turns ago) but the *contract*: first-class means a bad form goes red at Check, not dead at Run — hence probe-transpiling every raw row so reader, expander, and emitter all speak before anything executes. The owner's own phrasing contained the crucial scope cut: "any *cell* that begins with (" — one form per row — which sidesteps the progressive Check false-redding a multi-row form's interior, and turned a limitation into a recorded dependency (multi-row forms wait on V1). Then the maiden run delivered the phase's best joke: the malformed-form pin used `(if x)`, and the engine *refused to refuse it* — a clause-less If emits as vacuous legal VBA, the 1:1 doctrine holding firm against its own test author. **When pinning a refusal, first prove the refusal exists.**

## XXVI. The audit wore five hats, the roadmap became a graph, and the diffs got a witness

Alpha 2 opened with a five-perspective audit whose one discipline was *receipts*: every criticism had to point at something actually read in the code this session — the quadratic Check, the `EN_Sheet` one-program limit, the absent macroexpander, the dialect-override hole that E2's own plan would have turned into accidental precedence. Then the sequencing note stopped being a list and became a dependency graph with a one-line proof per band: tooling before surface, surface before freeze, freeze before strangers, trust before the pilot, the pilot before demand-ranking — read backwards, each band justifies the one above it. And the collaboration itself got its missing instrument: git, adopted not as backup but as the *witness to blind edits* — the diff is the mechanical answer to "did the change actually arrive," the empty diff is the alarm this thread once needed, and the tag on each verified state makes "the printed baseline is the authority" a thing you can diff against. The method keeps converting its incidents into infrastructure; that remains the real product.


# Part Four — Audit I (V1–V5): the session the product met the world

## XXVII. The quadratic died by attribution, not re-derivation — and the veto had a witness

V1 retired the progressive-prefix Check not by making re-translation faster but by making it unnecessary: one translation, then a ladder of attribution (the error's own line, a unique quote, the last row) — and the single refusal that genuinely needed the old loop was taught to carry its line instead. The fast-run half produced the pass's best veto: wrapping `main` in `with-fast-excel` would have displaced the step handler (C1's untrappable re-raise, working against us one frame in) *and* changed semantics — manual calculation makes a program that writes a formula and reads it back read stale values, and `instructions.txt`'s own B3 sum was the standing witness that would have failed. **When a proposed optimization has a semantic edge, look for the regression program that already proves it — the veto that cites a runnable witness never has to be argued twice.** And the pass planted a measurement (the Check timing line) precisely so the *next* optimization gets promoted by a number, not a feeling.

## XXVIII. One tag, one unit — the dual-tag strengthening

V4's suggestion read "sentence line as the `vla:` tag," and implementing it literally would have made one tag mean two units depending on provenance. The shipped `' vla:X src:N` dual tag keeps every coordinate honest and makes the round trip explicit in the text. The mechanism — an `(at-line N …)` annotation form with dynamic extent — joined `begin` and `raw` in the don't-tag-the-delegator exclusion, the one place a duplicate tag could sneak in. **When threading metadata through layers, never overload an existing field with a second meaning; add the second field and let both stay true.**

## XXIX. The owner's ear is a test suite: Store, pairs, and the dissolved refusal

Three revisions in one pass family, each a correction the author had rationalized. `Remember … under` beside `Remember … as` was defended as "one verb, two tails" until the owner named it: name-binding and container-filling are two *mechanisms*, and lookups lack the sentience to remember — `Store` took the container. The pair-walk ask looked like parser surgery and turned out to *dissolve* a refusal: V3 refused walking a lookup because the two representations disagree on what a raw walk yields; emitting `VlaDictPairs` means no raw walk is ever emitted, so the ambiguity the guard protected against ceased to exist. And the keyed read (`prices for code`) shipped scoped *hard* — live only for registered lookup names — so a new infix changed no existing rule's greediness contract. **A refusal guards an ambiguity; if a design change removes the ambiguity, remove the refusal — guarding a ghost is its own bug. And audition verbs against the speaker twice, because the author's second rationalization sounds exactly like the first.**

## XXX. Identity as pure functions, and the state that was already scoped

V2's multi-program design put the entire identity question — which workspace, which module, which snapshot prefix — into three pure name functions, pinned ten ways without a workbook in hand, with one load-bearing invariant: tags contain no underscore *by construction*, so snapshot names can never parse ambiguously. The capture doctrine extended one level down (a button click IS its sheet), colliding tags refuse loudly at three gates, and the audit's predicted "state row per program" turned out to already exist — the imported path, marks, and text live on the sheet and rode along free. **Before building per-X state, inventory what is already keyed by X; the migration you skip is the one that cannot regress.** (V2.1's corollary, owner-added: every command must live on the surface that exists *pre-build* — the sheet's own buttons — because the menu is born only with the `.xlam`.)

## XXXI. Blind UI ships labels, and silent loaders get loud pins

The ribbon was authored blind, so every choice optimized for graceful degradation: label-only buttons (a wrong `imageMso` degrades the ribbon; a missing image degrades nothing), one callback dispatching by id (three surfaces, zero drift), PowerShell package injection over Shell32 flakiness or an unverifiable hand-built template, soft-failure with the legacy menu as permanent fallback. The contract between XML and dispatcher is pinned in the self-test because Excel's ribbon loader fails *silently* on a mismatch — the one failure mode worse than a loud one. **Where a platform swallows errors, move the contract into your own suite; where you cannot verify an asset, choose the variant whose failure is cosmetic.** The Mac spike's whole yield was honesty: Run refuses in one sentence, Check keeps working, and the portability inventory revealed two earlier passes (V3's fallback, the clipboard sheet) as accidental spike prep.

## XXXII. The topology lesson: the dev machine was lying the whole time

The session's defining bug: generated code in the user's workbook called helpers that lived only in the add-in, and **VBA has no cross-project call** — masked since Phase A's `VlaColor` because the dev workbook, which held the helpers, was always the host. No dev-topology test could ever catch it; only the first true standalone run did. ## The lessons

**1. A ten-minute deliberate-defect test outranks any design argument (S4).** The pre-run compile probe was reasoned, documented, veto-invited — and dead on arrival: VBA's default Compile On Demand compiles per *procedure*, so the sacrificial call verified nothing, and compile errors cross `Application.Run` as untrappable modals, killing the entire in-VBA probe family (AddressOf variants included). One owner test, three F5 presses, a whole solution category permanently retired before it shipped false confidence. Corollary: when a mechanism claim is load-bearing, test the claim, not the feature.

**2. When you generate the text, you know the universe — static checks beat runtime compilers (S4.2).** The resolve check catches the realistic failure class (typo'd vla-helpers from dialect templates — V5.3's class, multiplied by every future phrasebook author) at Check, at the offending row, naming the helper. Modal-free by construction and, unlike the probe, fully self-testable. The general form: prefer verifying artifacts you produced over provoking the platform's judge.

**3. Never store state across a boundary the machinery itself destroys (S5.0 → S5.4).** The trace flag died three ways: module state (the Run's own compile wipes the running project's variables — project state loss), then a workbook-Name-backed flag (survives recompiles, but two topologies mean two `ThisWorkbook`s — the Immediate window armed the add-in's copy while `main` read EN_Runtime's). Caught by S1's determinism pin two days after the pin shipped — the microscope watched the microscope, on a bug every prior audit had walked past because nothing could see it.

**5. A module that fails to compile silently runs its old self (S5.4).** A `Dim` welded onto a signature line failed `VLA_IDE`'s whole compile — so every "fix" in that module was inert, the old code kept running, and three separate symptoms (dead trace, empty-run box, phantom guard) were one masked cause. Same pass: uploaded files can carry *partial prior implementations* — read what exists before writing what was asked; disk is truth.

Diagnostic-first: two failed trivial fixes means the model is wrong, not the conditional (S5, the parting bug — backlogged).** Three blind guards shipped against the empty-Run box; all three simulated correctly; the box persists. **7. "The dialog paraphrases my sentence" — the step table now quotes the user's original text, case and all. # LESSONS — Addendum: the Band-1 / G-line session

**1. New features meet old gates — fix the gate, pin the incident.** All four maiden-run incidents shared one shape: a shipped gate predating the feature it judged. The resolve check predated carried macros (L4.1: the first phrasebook macro drew the missing-helper dialog); the alternation classifier predated single-branch surface forms (G1.2: "alternation = contains |" was too narrow, and the failing pin's vector was *right*); the suite predated crash-proofing (L2.1: one raise killed every section after it); the timing harness predated its own context problem (V6.1/V6.2). **2. This engine's defmacro puts the name INSIDE the signature list — and the wrong dialect has now bitten three times.** `(defmacro (twice x) …)`, never `(defmacro twice (x) …)`. First the L2.1 pin crash, then the resolve-check name reader, then the vocab-macro name extractor. Read the prelude's own spelling before writing a defmacro anywhere; the L2.1 comment is the canonical citation.

**4. A reset inside a test section is a fence.** Everything depending on earlier registrations runs before it (G1.3: the G1.2 block's `EnglishResetGrammar`, inserted mid-section, wiped the rule a later pin needed — and the failure message contained its own diagnosis, "all 12 sentences").

Corollary: an Immediate-window call inherits whatever Excel last had active — the IDE's click supplies activation implicitly, and nothing else does.

The owner-proposal loop went four-for-four, and the division of labor is the method.** Human aesthetic instinct proposes the surface (stem/suffix, bare pipes, set-formula, the functor sweep); the implementation scan supplies the invariant that makes it sound (stem-binds; **braces capture, bare matches**; the dot stays first-class one expansion down; fired-only emission). Reusable for every "approved future shape" the project records.

## Beta — the vocabulary-grammar migration, banked ahead of the rewrite

1. **Comment characters split by whether their content is quote-protected, not by file extension for its own sake (revisits Alpha 1).** Alpha 1 debated `;` versus `#` project-wide and chose `#` everywhere, because a semicolon is valid English punctuation and a stray one in raw prose is genuinely ambiguous with a comment start. That risk was real for `instructions.txt` - its sentences are unquoted, bare program text - and it stays on `#`, unchanged. It was never real for `.vla` files: every piece of English content a vocabulary file carries (pattern text, test sentences, message fragments) is a quoted string argument, and no tokenizer treats a quote's interior as comment-eligible - `prelude.vla`/`hello.vla` already prove it, coexisting with `;` comments today with zero friction. `english.vla`'s upcoming grammar migration adopts `;` (VLA's own convention) for exactly this reason. The general form: a shared risk deserves a shared rule, but two file types with genuinely different exposure don't owe each other consistency.
2. **Repetition is a legitimate design instrument, not a code smell, the moment the goal is branding rather than information density (the `<lingua>-vla` naming debate).** The proposal was to name every phrase-rule directive after its own source language - `english-vla`, and eventually `deutsche-vla`, `espanol-vla` - baking the same fact into every one of a file's 300-plus directives. First reflex: reject it as redundant, since the file already establishes its own language once. Wrong instrument for the question. The owner's actual goal was psychological - "I want people to think 'I'm converting my native tongue into VLA' every time they write a rule" - and a repeated word is not waste when repetition is the mechanism, not an accident; that is what branding *is*. The assistant's own first counter-argument then failed a second, sharper way: "every dialect will type a different word, so there's no shared word at all" - true of the varying PREFIX, and exactly backwards about the CONSTANT SUFFIX, which is on every directive, in every file, forever. `en.wikipedia.org`/`de.wikipedia.org` was the example that made it click: the shared suffix is what makes every dialect feel like one project, and the varying prefix is what makes each one *theirs* - the same structure, arrived at independently, already proven at civilizational scale. The general form: when someone's design goal is stated as psychological or rhetorical, don't grade the proposal on engineering metrics it was never trying to optimize - find the actual precedent for the *stated* goal before arguing against it on a different one.
3. **A structural insight can hide a free correctness check inside it, and offering the check is not the same as requiring it.** Once directive heads carried their own language, the obvious next move was "so require one language per file, and the mismatch becomes a load-time catch." Proposed unprompted, and declined unprompted right back: the owner wants polyglot `.vla` files kept open as a real future option, not foreclosed by a convenience check nobody asked for. The tell, in hindsight: the "free" check would have added file-level state to a loader that otherwise needs none at all - every directive already self-describes, so enforcing uniformity is the only thing that would have made the design *more* complicated, not less. A win offered alongside a design should be inspected for what it would cost the design's own stated openness, not just for whether it's cheap to build.
4. **A reset that looks like success is invisible until the one assertion that needs failure to still be there actually runs (LISTOPS-BUDGET's own self-test).** A written stress test built a 250-link recursive macro chain specifically to prove the engine's depth guard fails LOUDLY instead of silently truncating - and the pin built to prove that loud failure failed on its own first run. Cause: `On Error GoTo 0` resets `Err.Number` (and `Err.Description`) to zero the instant it executes, and the pin read `Err.Number` inside the `Report` call *after* `On Error GoTo 0` had already cleared it. Two sibling pins in the same Sub read the identical pattern to check `Err.Number = 0` (expecting success) and passed regardless of whether they should have - a genuine success and a silently-reset failure are indistinguishable at that read, so the bug hid in every assertion direction except the one that actually demanded a real error still be present. The fix matches a discipline this codebase already keeps for `Err.Description` everywhere (capture to a local immediately after the risky call, before the reset can reach it) - the miss was applying it to the text and forgetting the number needed the identical treatment. The general form: **when a language can silently clear its own error state through ordinary control flow, a check for the ABSENCE of a problem cannot distinguish a reset from a resolution - only a check that demands the PRESENCE of a specific failure will ever catch the clearing, and among several identical-looking checks, it may be the only one that does.**
5. **A harness that silently reads whoever wrote last is a harness that lies about which of two things it's testing (`VerifyReports`' stale-read bug).** `VerifyReport()` was documented, in its own neighboring comment, to require that the caller run a real Compile-and-Trace immediately before calling it - "VerifyReport must run FIRST, while the Output sheet still holds whatever a prior manual emitter Run left behind." A comment is not an enforcement mechanism, and G-STRUCT's own live-testing session violated the precondition constantly and invisibly, simply by doing the ordinary thing a two-backend project's own debugging requires: running Compile-and-Trace and Interpret-and-Trace in whatever order the moment called for, while chasing an unrelated bug. Every violation produced a fully-formed, plausible-looking report - real cell addresses, real "not bold" / "got empty" failures - with nothing in its shape to distinguish "the emitter's rule is wrong" from "you're reading the interpreter's leftover cells and it says 'emitter' on the label." The fix was not a sharper warning in a comment nobody re-reads mid-debugging; it was a durable, workbook-level marker (`VlaStampRunProvenance`/`VlaReadRunProvenance`, a defined Name, the same durability trick `VLAt_TraceOn` already uses) written by every real Run and Interpret path, checked by `VerifyReport` before it trusts a single cell, refusing loudly - naming which backend actually wrote what it's looking at - instead of grading the wrong homework silently. The general form: **when a check's correctness depends on an unenforced precondition about WHO wrote the state it's reading, that dependency will be violated by ordinary, blameless use of the tool - the fix is not a louder warning, it is making the state self-describing, so a violation fails at the check itself instead of manufacturing a plausible answer to the wrong question.**
6. **A value borrowed from one query to answer a second, different question is a latent bug even while it happens to work - and the fix that actually matters can arrive disguised as an unrelated one (TER-4's real conclusion, `docs/TRENCHES.md` Part Two).** The bug that reverted PasteSpecial'd formatting on one sheet, chased across two sessions and most of a working day, turned out not to be about reverting anything: `VlaTrimSheet` used a single row-order `Find` to answer two separate questions at once - "what's the last used row" and "what's the last used column" - because one cell's `.Row` and `.Column` were both sitting right there for the taking. Row-order search only answers the first question correctly. `fill-series` wrote real values down to row 203, but only in column A; other real content sat in columns further right, at shallower rows - so the same call that correctly found the last row silently reported the sheet's rightmost column as column A, and a delete loop that was never wrong on its own terms correctly, faithfully deleted almost every column from B onward, including the one two "unrelated" rules happened to write into. Nothing had reverted. It had been deleted, in full view, the entire time. This was found not by reasoning harder about the original question but by fixing an adjacent, smaller, fully-understood bug (`Find` also missing cells with formatting and no content) for its own sake, unrelated to the mystery on paper - and only afterward discovering, almost by accident, that re-running the original failing scenario against that unrelated fix made it pass. The general form: **a shortcut that reuses one lookup's result to answer a second question it was never asked is a bug waiting for the day its two questions have different right answers - and when a stubborn bug won't yield to direct investigation, fixing a smaller, adjacent, honestly-diagnosable bug and checking whether it moved the needle can find the real answer faster than one more theory about the bug you already have open.**

7. **A known, catalogued hazard still gets written twice, because a catalogue is consulted after the crash, not before the keystroke (PROLOG.4, QUERY AND LOGIC).** `VLA_Prolog.bas`'s new backtracking solver hit two hazards this project had already named and numbered: a `Private Const` for the resolution-step ceiling was declared between two already-defined procedures instead of in the module's own declarations section - hazard 11 by name, D1.1's own incident, cited twice already in this file and in `PROJECT_BRIEF.md`'s numbered hazard list - and, worse, `Dim newGoals As New Collection` sat inside a `For Each` candidate-clause loop, the exact As-New-in-a-loop trap this same module's own `ParseProgram` had just been written to avoid, a hundred lines above it, in the SAME pass. Both compiled or ran clean on the simple cases (a fact clause contributes zero extra goals, so there was nothing stale to leak) and only a genuinely recursive case - a self-referential rule backtracking across two candidate clauses - exposed the second one, and it did not fail loudly: the corrupted, ever-growing goal list made a three-fact chain that should resolve in roughly fifteen steps instead blow through a thousand-step safety ceiling, presenting as a *plausible, differently-worded refusal from a different subsystem* (a resolution-step-budget message) rather than as an obviously wrong answer. Neither hazard was novel to discover; both were already written down, in this exact file, before this pass started. The general form: **a hazard catalogue only pays for itself at the moment of writing new code, not at the moment of once having read it - the fix is not a longer list, it is treating the existing list as a checklist run against every new loop and every new module-level declaration before calling the code done**, the same discipline the compile gate already enforces mechanically for the syntax-shaped half of this hazard and that nothing yet enforces for the semantic half.
