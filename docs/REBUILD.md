# REBUILD — the target module topology

*What the `.bas` files should be **shaped like** if they were written again from
nothing, given what `BETA_ROADMAP.md` now says the project is for. Strategy, not a
schedule: no pass IDs, no checkmarks, no dates. The ledger holds passes; the
roadmap holds order; this file holds **shape**.*

*Companion to `BETA_ROADMAP.md`, and downstream of it in exactly one direction: every
module below must name the roadmap items that pay for it, or it does not get
created. A topology that cannot cite its debts is architecture as decoration.*

**Revision note, second pass.** The first draft assumed one backend, because the
roadmap it was written against did too. THE TWO NEUTRALITIES restores the interpreter
(`IN.*`, Alpha 1's `F1`), which promoted the head table from *a tidy refactor of
a `Select Case`* to *the fork point of the entire pipeline* and demoted module
injection from an architectural given to one optional capability among two. This
pass then swept every proposed name for ambiguity (R11, Appendix D) — and that
sweep caught a real layering error, recorded in Layer 3, which is the argument
for declarative names making its own case.

**Third pass.** IN.9 resolved the backend question the second pass left open:
**the interpreter is the runtime and module injection is an export.** Layer 2's
boundary constraint and the whole `VLAX_` tier move off the default path; Layer
4's injection module leaves it entirely; the harness gains an effect-log golden,
because the primary behaviour witness lived on the path that was just demoted.
This pass also **corrects a false claim** the second pass made about plate 4 —
see §0, where the correction is stated rather than edited away, since a document
that quietly fixes its own errors teaches nothing about how it was wrong.

## 0. THE THESIS, AND THE ONE MEASUREMENT THAT MATTERS

The roadmap's audit reached two verdicts the current file layout cannot honour.
**Lexically, the pipeline is not ready for a second language** — 63 English head
words in emitter arms, 102 locale-dependent identity folds, 169 hand-written
refusal strings, and sentence machinery welded to English block words.
**Structurally, it is not ready for a second backend** — `VlaTranspile` is
source→VBA-text, head dispatch is a `Select Case` with exactly one consumer, and
nothing anywhere declares that VBA is a *choice*.

Both gaps have the same shape: **an assumption that was free to make when there
was one of everything, and is priced per site once there are two.** The
FORTIFICATIONS section opens with the sentence "every boundary is currently held
by habit." This document is that sentence applied to the directory listing,
now with two boundaries instead of one.

**The acceptance criterion for any rebuild, stated before any design:**

> A rewritten pipeline is correct when `instructions_golden.vla` and
> `instructions_golden.vba` regenerate with an **empty `git diff`**, the self-test
> prints its baseline count with zero failures, `VerifyReport` comes back green
> on H1:H31, **and — once the interpreter exists — `instructions.txt` produces
> identical Output sheets under both backends.**

That last clause is not new. It is Alpha 1's definition of done for F1, written
before this document existed, and the instrument that checks it was built in
Alpha 1's **A0**, whose stated purpose included "pre-builds F1's dual-mode parity
harness." The harness has been maintained continuously ever since. It was
waiting.

**The Whitworth caveat, filed now so it cannot be forgotten later.** Three plates
converge on flatness with no external standard — but they converge on
*consistency*, not truth. The goldens were generated by the implementation being
replaced; if the old emitter was wrong, a perfect diff reproduces the wrong
answer perfectly. So the rebuild runs **plates that do not share a lineage**:

| Plate | What it is | What it can catch |
|---|---|---|
| 1 | the new pipeline's emitted text | — |
| 2 | the committed goldens | any behaviour change vs. the old implementation |
| 3 | `VerifyReport`'s cell values after a real Run | errors both implementations share, because it reads Excel, not text |
| 4 | the same corpus run through the **emitter export** | divergence between the two backend implementations — and nothing else |

**Correction, recorded rather than silently fixed.** An earlier draft of this
file claimed plate 4 catches "errors shared by everything upstream of the
backend — reader, expander, sentence layer." That is false, and it violated the
Whitworth caveat sitting two sentences above it. A mis-parse upstream reaches
*both* backends identically, both produce consistently wrong output, and plate 4
goes green. Two implementations of one semantics converge on **consistency, not
truth** — which is precisely what the caveat says and what the draft then
forgot.

What plate 4 is actually worth, which is still a great deal: **implementing every
form twice forces the project to say what the form means.** A semantics that
exists in one emitter is whatever that emitter happens to do; a semantics that
must be reproduced by an independent evaluator has to be *stated*, and R9 is
where the statement gets enforced. That is specification pressure, not error
detection, and it is the honest case for paying the two-backend tax. **Plate 3
remains the only instrument that touches the world.**

## 1. WHAT VBA FORCES, WHICH IS WHY THIS IS NOT A NORMAL LAYERING DOCUMENT

Six constraints shape every decision below. They are not preferences and they do
not negotiate.

1. **There are no namespaces.** Every `Public` in a project shares one global
   name space. Module boundaries are documentation unless a naming convention
   makes them legible. Prefixes are the only namespacing available, so prefixes
   become load-bearing — and so does every other syllable of a module name,
   which is R11's whole basis.
2. **There is no link order and no import graph.** Any module may call any
   module; circularity is legal and silent. A layered design in VBA is a *lint*,
   not a language feature — the layering must be **declared in a header and
   checked by a tool**, or it will be layered on Tuesday and a spaghetti bowl by
   Friday.
3. **Compile On Demand compiles per procedure.** More modules buy no compile
   safety. Whole-project `Debug → Compile` remains the gate. Splitting files is
   about *change locality*, never about verification.
4. **A module that crosses into a user's workbook must compile alone.** VBA has
   no cross-project call. This is the entire reason the runtime helper zoo is a
   separate module — and it is a constraint that **applies only on the transpiler
   path**, which is the single largest structural consequence of the
   interpreter's arrival.
5. **Editing a running project resets module-level state.** Any design that
   stores state beside code and reads it after a recompile is already broken.
6. **`CallByName` is the only late-bound member dispatch available, and it is
   slow.** The interpreter's inner loop is a member-name lookup, which sets the
   shape of `VLA_Interpreter` — cache resolved members per call site, or accept
   an order of magnitude — and is the technical root of IN.8's honesty item.

## 2. THE STANDING DECISIONS

Eleven rules. Each expands at every file written afterwards, so each is stated
with its reason attached — the engineer of 2031 finding one of these fences
should be able to tell doctrine from fossil and demolish accordingly.

- **R1 — every module cites its debts.** A module's header names the roadmap
  items its existence pays into. No citation, no module. *Why:* the proportion
  test made structural; it is what stops a rebuild becoming a hobby with thirty
  files.
- **R2 — dependencies point down, and a lint says so.** Each header declares
  `LAYER: n` and `MAY CALL: <modules>`. *Why:* see constraint 2.
- **R3 — the prefix decides shipping, and the build derives its manifest.**
  `VLA_` ships inside the add-in; `VLAX_` additionally crosses the injection
  boundary; `VLAT_` is dev-only. The build and reload rig compute their lists
  from the prefix and **refuse any module matching none**. *Why now:* there are
  today two hand-maintained module arrays that must agree and are not checked
  against each other.
- **R4 — 1,200 lines is the budget.** *Why:* `VLA_English.bas` is 5,294 lines and
  `VLA_Tests.bas` is 4,493. Both crossed the line where a reader stops holding
  the module in their head, and neither crossing was noticed, because nothing was
  watching.
- **R5 — no user-facing text outside the catalogue.** *Why:* **169 `Err.Raise`
  sites**, every message a hand-written English string. SD-2 banks the discipline
  today; this rule is where it becomes structural.
- **R6 — no `LCase$` outside `VLA_Identity`.** *Why:* **133 `LCase`
  occurrences**, ~102 deciding identity. VBA's `LCase` is locale-aware. A lint is
  the only thing that keeps the 103rd from being typed.
- **R7 — self-containment is a boundary rule, not a global one.** The discipline
  "modules are self-contained; duplicate small helpers rather than share
  Privates" was earned by the injection topology. It applies to `VLAX_` modules
  and **not** to compiler modules, which always ship together.
- **R8 — run state lives in the context, never at module level.** *Why:* **17
  module-level variables in `VLA.bas` and 62 in `VLA_English.bas`** are what "the
  compiler is not reentrant" means in practice. *Extended by the interpreter:* the
  interpreter's variable frames are context state too, so the context is shared
  machinery rather than a compiler convenience — which is why R8 now says *run*
  state rather than *compile* state.
- **R9 — no core form without both backends, or a declared refusal.** A head
  symbol the emitter implements and the interpreter neither implements nor
  refuses **in words** is a failing test. *Why:* silent divergence between
  backends is the bug class that makes multi-backend systems unmaintainable, and
  it is cheap to forbid while there are two rather than three. This is SD-5 made
  mechanical, and it is the rule that keeps `VLA_HeadTable` honest. *The reason
  worth stating plainly, since parity's error-detection value is narrower than it
  looks (see plate 4):* a semantics implemented once is whatever that
  implementation happens to do; a semantics that must be reproduced independently
  has to be **stated**. R9 is where the two-backend tax buys a specification.
- **R10 — nothing above Layer 1 names a backend.** The sentence layer, the
  phrasebooks, the commands and the panel refer to *the backend in force*, never
  to "the transpiler." Layer 1 modules may and should name their backend — that
  is what they are. *Why:* this is SD-1 with an address. The moment a template, a
  rule, or a command branches on `IsTranspiler`, backend plurality has become a
  conditional rather than an architecture, and every later branch is cheaper to
  add than to remove.
- **R11 — a module name is a claim about contents, spelled out.** Whole words,
  no abbreviation unless the abbreviation is what the domain itself says; the
  name states what the module *decides* or *produces*, not the layer it sits in;
  and no two names in the project may differ only by punctuation or case. *Why:*
  constraint 1 — there are no namespaces, so the filename is the only interface
  documentation guaranteed to be read. *Why it is a standing decision and not
  taste:* the first draft of this file proposed `VLA_Ctx.bas` beside a
  `VlaContext.cls`, which is SD-9's homograph failure reproduced inside the
  document that records SD-9. A rule catches that; vigilance had already
  demonstrably failed. **The audit that produced this rule is Appendix D**, and
  it changed nineteen names and found one layering error.

## 3. THE TARGET TOPOLOGY

Five layers plus a harness. Calls point downward only.

### Layer 0 — Ground *(no dependencies; everything depends on these)*

| Module | Replaces | Pays into |
|---|---|---|
| **`VLA_Identity`** | scattered `LCase$`, `Replace`, string building | LX.3, SD-8, P-TOK, EN.4, LX.6 |
| **`VLA_Messages`** | 169 raise sites, every hand-written string | F.6, SD-2, LX.2, LX.8, CO.1, LE.2, DO.2 |
| **`VLA_Context`** | 79 module-level variables | F.5, IN.2, AS.3, P-PROF, U.14 |

`VLA_Identity` exports exactly two comparison verbs and refuses to be a junk
drawer: `Fold(s)` — invariant ASCII, decides identity — and `SameText(a, b)` —
locale text comparison, for things a user typed and meant as words. Naming them
for what they *decide* is the whole point; `LCase` was ambiguous by construction
and 102 sites inherited the ambiguity. The string builder rides here because it
is the only other text primitive with no dependencies, and the header says so.

`VLA_Messages` is the catalogue plus the single `Raise(id, at, params…)`. English
is the default catalogue, loaded as data with a compiled-in fallback so a missing
catalogue still speaks. The catalogue file *is* the error reference, so DO.2 stops
being a document anybody has to write.

`VLA_Context` holds one compile's world — macro table, doc table, source map,
line offset, expansion budget, phase timers, trace flags — **and one execution's
world: the variable frame stack, the call stack, the current step.** That the two
want the same object is not a coincidence. A compile and an execution are the
same walk over the same forms with different terminal operations, and F.5 was
always going to be IN.2's foundation.

> **Adjudication required before line one: class or record?** A `VlaFrame.cls`
> gives push/pop nesting for free and costs one entry in three lists. A `Type`
> plus a stack array keeps the project all-`.bas` and costs manual field
> plumbing. Recommendation: **the class, and more firmly than before** — the
> interpreter needs per-call frames, and frames are the textbook case for
> objects. *Named `VlaFrame`, not `VlaContext`, under R11:* one instance is one
> frame, the module is the stack of them, and `VLA_Context` beside `VlaContext`
> would differ only by an underscore. Still the owner's call, and still the only
> decision here that changes the file-extension inventory.

### Layer 1 — The core language *(where the fork lives; the only layer that may name a backend)*

| Module | Replaces | Pays into |
|---|---|---|
| **`VLA_Forms`** | "list = Collection, atom = String with a quote-char marker" | F.2, AS.4, G-RENDER, P-NTH, P-DICT |
| **`VLA_Reader`** | tokenizer + parser halves of `VLA.bas` | P-TOK, AS.5, EN.4, EN.5 |
| **`VLA_Expander`** | macro expander + `PreludeMacros()` | F.3, IN.2, P-PRELUDE, L.11 |
| **`VLA_HeadTable`** | the emitter's `Select Case` arms | **IN.1**, LX.4, R9, AS.2, AS.8, F.1, F.7 |
| **`VLA_VbaStatements`** · **`VLA_VbaExpressions`** | the emitter body | F.1, PF.2–PF.5 |
| **`VLA_Interpreter`** | *nothing — new* | **IN.2**, IN.5, IN.7, EN.6 |
| **`VLA_FormulaEmitter`** | the `deflambda` / formula-dialect paths | F.7, EN.2, EN.3 |

**The four backends are now legible from the file listing alone**, which is R11
doing the job it was written for: `VLA_VbaStatements` + `VLA_VbaExpressions`
(emit VBA), `VLA_FormulaEmitter` (emit Excel formula and LAMBDA),
`VLA_Interpreter` (emit effects), and — in Layer 3, for the reason recorded
there — `VLA_EnglishRenderer` (emit sentences). Under the old names
(`VLA_EmitStmt`, `VLA_Formula`, `VLA_Eval`, `VLA_Render`) that set was invisible,
and a set you cannot see is a set nobody keeps complete.

Four structural moves carry this layer. The first two are load-bearing.

**`VLA_HeadTable` is the fork point, and its name is now its contents.** One
registry, one row per core form:

```
symbol │ aliases │ arity │ interpreter routine │ vba routine │ formula? │ export-only?
```

Every architectural ambition in the roadmap that touches Tier 1 is a column of
that table. LX.4's alias table is column 2. IN.1's backend interface is columns
4–5. F.7's declared formula subset is column 6. IN.5's export-only surface is
column 7. R9 is the assertion that no row has a filled VBA cell, an empty
interpreter cell, and no refusal — and under IN.9 that asymmetry is the right way
round, since the interpreter column is the one every user meets. AS.2's coverage
has a denominator because rows are enumerable, and AS.8's parity coverage is a
join of the table against the pins.

This is why the head table must exist **before** Grammar and before the
interpreter, and it is the single most important sentence in this document:
*while dispatch is one `Select Case`, adding a backend is a data change;
afterwards it is sixty-three sites, twice.*

**`VLA_Interpreter` is a peer of the emitters, not a subordinate.** Alpha 1's
design stands unmodified: `ExecStmt` / `EvalExpr` mirroring the emitter's
structure, `CallByName` for member dispatch, per-call variable frames in
`VLA_Context`, dedicated handlers for named-argument templates. It reads the same
forms `VLA_VbaStatements` reads and dispatches through the same table. It does
not call the emitters and they do not call it; they are siblings whose only
shared knowledge is the table and the form ADT.

**`VLA_Forms` is the ABI between tiers.** F.2 — "English emits FORMS, not
strings" — is unbuildable until there is an API to build forms *with*. Under one
backend that was an ergonomics argument. Under two it is a correctness argument:
text emitted for the VBA backend is text an interpreter would have to re-parse,
and a pipeline that re-parses its own output has two grammars whether it admits
it or not. *(Plural deliberately: `VLA_Form` singular reads, in a VBA project, as
a UserForm — R11's ambiguity test, applied to a name I nearly kept.)*

**The prelude is `prelude.vla`, and `VLA_Expander` loads it.** As a file it gains
lint coverage, becomes editable by non-VBA contributors, deletes a bug class, and
subsumes P-PRELUDE. **The new reason:** an interpreter must implement the
prelude's verbs, and it can only do that if they are enumerable rather than
concatenated into a 320-line string function.

### Layer 2 — The runtime *(crosses the boundary only on one path)*

| Module | Replaces | Pays into |
|---|---|---|
| **`VLAX_RuntimeHelpers`** | `VLA_Runtime.bas` | IO.3, EN.6, PF.4, L.11, AC.1, IN.2 |

Stays one module, because constraint 4 says so **on the transpiler path**: the
exported copy compiles alone or the user's generated code raises "Sub or Function
not defined" the moment the dev workbook closes.

**What the interpreter changes here is the caller, not the module.** Under the
transpiler, `VLAX_RuntimeHelpers` is injected beside the generated module and
called in-project by generated code. Under the interpreter, the *same procedures*
are called in-process by `VLA_Interpreter`, inside the add-in, with no injection
and no export. One helper zoo, two callers, one set of semantics — which is
precisely why the zoo was split out at V5.3 and why that split has aged well.

R7 therefore still binds this module: it must remain compilable alone, because
one of its two callers still requires that. A constraint that applies on one path
applies to the module.

> **Adjudication required: how does the catalogue cross the boundary?** R5 says
> user-facing text comes from `VLA_Messages`; constraint 4 says the injected copy
> cannot call it. Recommendation: the build **generates** a frozen subset of the
> catalogue — runtime-reachable IDs only — into the exported copy from the same
> source, so there is one authored catalogue and one derived one. *Note that the
> default runtime does not have this problem at all* — it was always an artifact
> of the injection boundary, and under IN.9 it is a cost paid at export rather
> than a cost paid by every user of the product.

### Layer 3 — Sentences

| Module | Replaces | Pays into |
|---|---|---|
| **`VLA_Sentences`** | block parsing, slot binding, output assembly | LX.5, LX.10, G6, G7 |
| **`VLA_Matcher`** | the DCG matcher, first-token dispatch | F.4, LE.2, LE.3, P-PROBE |
| **`VLA_Phrasebooks`** | phrasebook load, directives, audit, provenance | F.1, F.10, LE.9, CO.2, CO.3, GO.1 |
| **`VLA_EnglishWords`** | every English word in the sentence machinery | LX.1, LX.5, LX.9, LX.10 |
| **`VLA_EnglishRenderer`** | *nothing — new* | **G-RENDER**, AS.4, LE.1 |

> **The layering error the rename caught, recorded rather than quietly fixed.**
> The previous draft filed rendering in Layer 1 as `VLA_Render`, "a third
> consumer of the head table." Spelling the name out as `VLA_EnglishRenderer`
> made the contradiction visible in one reading: rendering forms back to
> *English sentences* requires the phrasebook patterns run in reverse, and
> phrasebooks live in Layer 3. A Layer 1 module cannot call up. The vague name
> hid a dependency inversion for an entire revision; the declarative one could
> not survive its own first sentence. **What genuinely belongs in Layer 1 is
> form → canonical VLA text** — which already exists as `VlaFormat` and is a
> `VLA_Forms` responsibility, not a new module. Two different renderings had
> been collapsed by one imprecise word.

This layer is LX.5 executed, and it decides whether a second language is a
**sibling module or a fork of five thousand lines**. The test of whether the line
was drawn correctly is mechanical and should run as a lint: **`VLA_Sentences` and
`VLA_Matcher` contain no English word literals.** Not `"done"`, not
`"otherwise"`, not `"greater than"`. Those move into tables `VLA_EnglishWords`
owns, and the sibling name a second language would take — `VLA_SpanishWords` —
is obvious from the first, which is R11 paying for itself again.

That point is larger than it looks. Phrase rules are already data — the thing the
project got right early. The **structural** grammar is not: `If`, `Repeat`,
`Try`, `To`, `Done.`, `Otherwise`, `When` are hardcoded comparisons scattered
through the parser. While that is true, a Spanish phrasebook translates the verbs
and not the sentences, which is a demo rather than a product.

*(Session note: `scripts/pirate.vla` and its six siblings — phrase-rule-only
dialects, zero structural-grammar changes, riding the existing macro layer
untouched — are exactly this "demo" shape, empirically now. Cheap to build,
proving nothing about the harder half this paragraph names.)*

`VLA_Matcher` holds the matcher, the dispatch index, F.4's conflict analyzer and
LE.2's near-miss finder together, because the roadmap has already noticed the
last two are the same math. Filing them apart guarantees two implementations of
one algorithm.

`VLA_Phrasebooks` carries the product's own word for the artifact — Alpha 1's E1
decided that `.vocab` files become *phrasebooks* in every doc and menu string,
and "vocab" is the engine's legacy term surviving in a place users now read. It
is also where **F.1's ABI is enforced rather than reviewed**: templates may
target prelude macros and `VLAX_RuntimeHelpers` verbs, never raw dot-forms, and
the loader checks every template's head symbols against the declared verb set at
load time. **Under two backends this stops being a style rule and becomes the
interpreter's feasibility condition:** every dot-form left in a template is a COM
incantation the interpreter must implement by hand. The roadmap's dot count — 61
of 102 rules, 120 dot-forms — is simultaneously F.1's scoreboard and IN.2's
estimate. `VLA_Phrasebooks` publishes it and fails a test when it rises.

**R10 lives here too.** No rule, template, or directive names a backend. A
phrasebook that says "under the transpiler" has already broken the architecture.

### Layer 4 — The product

| Module | Replaces | Pays into |
|---|---|---|
| **`VLA_Capabilities`** | scattered version/trust/platform checks | EN.1, **IN.6**, EN.6, EN.7, DI.2 |
| **`VLA_Commands`** | the orchestration half of `VLA_IDE` | F.11, U.14, V.1, AS.7 |
| **`VLA_ModuleInjection`** *(optional capability)* | VBProject manipulation, `VLA_Loader` | IO.1, IO.2, IO.3, DI.1 |
| **`VLA_Workspace`** | sheet↔program binding, snapshots, undo | U1–U5, U.15, IO.4 |
| **`VLA_Panel`** | buttons, colours, ribbon, dialogs | AC.1–AC.4, U.12, U.16, LE.1 |
| **`VLA_AddinBuild`** | `VLA_Build.bas`, manifest now derived | DI.1–DI.4, CO.3 |

Three cuts matter here. The interpreter added the second; R11 sharpened the
third.

**`VLA_Commands` never talks to a human.** Check, Run, Undo, Reload, Known
Sentences become functions taking a request and returning a result record;
`VLA_Panel` is the only module that may open a dialog or paint a cell. That one
line is F.11's pure/host split at the product layer, makes U.14 fall out for
free, retires the modal class from expected-error smokes, and makes AC.1 a change
in one module rather than a UI refactor. There are three `MsgBox` sites in the
runtime and two in the build today; afterwards both counts are zero and the lint
says so.

**`VLA_ModuleInjection` is an export feature, not a run path.** In the first
draft it was infrastructure named `VLA_Project` — a name that could have meant
the Frazaro project, the VBProject, or a user's workbook, and therefore
documented nothing. Under IN.9 it is not merely optional but **off the default
path entirely**: nothing in Check or Run reaches it, and it is invoked by one
deliberate user act, "export this workbook to standalone." The two properties
that justified it — a workbook outliving the add-in, and compiled speed — survive
intact as that button, which is exactly the test SD-11 sets for demolishing an
assumption rather than preserving it.

Two structural consequences follow, and both are wins the first draft could not
have. **`VLAX_RuntimeHelpers` stops being on the hot path** — its
self-containment constraint (R7) is now paid only when someone exports, though
the constraint itself still binds, since export is a real caller. And **the
`VLAX_` prefix tier shrinks to one module used occasionally**, which is the
clearest sign the injection boundary was generating incidental complexity for
every run in order to serve a minority of them.

**`VLA_Capabilities`, not `VLA_Env`.** It does not describe an environment; it
*decides* — which backend runs, whether LAMBDA is available, whether this machine
can be served at all. R11 asks names to state the decision, and EN.1's whole
point is that every other item needs a fact to branch on.

`VLA_Loader` disappears. Its file-import job is the include path F.3 already
needs in `VLA_Expander`; its module-injection job is `VLA_ModuleInjection`'s. A
138-line module duplicating two other modules' reasons to exist is a merge, not a
deletion.

### Layer 5 — The harness *(dev-only; `VLAT_` never ships)*

| Module | Pays into |
|---|---|
| **`VLAT_Harness`** — assertions, counters, section fences, guarded-call wrappers | F.8, AS.7 |
| **`VLAT_CoreLanguage`** · **`VLAT_Sentences`** · **`VLAT_Phrasebooks`** — the pure halves | F.8, F.11 |
| **`VLAT_HostRequired`** — everything needing a live Excel | F.11 |
| **`VLAT_Goldens`** — golden regeneration, `VerifyReport`, section markers, **the interpreter's effect log** | F.9, **IN.3.5**, CO.2 |
| **`VLAT_BackendParity`** — same corpus, both backends, identical Output | **IN.3**, AS.8, R9 |
| **`VLAT_Coverage`** — proof coverage, per-backend arm coverage, the R1–R11 lints | AS.1, AS.2, AS.8, LX.9 |
| **`VLAT_DevRig`** — reload, scratch eval, diagnostics, the phase timer | P-PROF, AS.3, IN.8 |

F.11 is the highest-leverage item in this layer and the reason the pure/host split
is a file boundary: **a human at a Windows box is the velocity ceiling and the bus
factor.** `VLAT_HostRequired` says which side of that line it is on in its name,
which `VLAT_Host` did not — "host" alone could have meant the host workbook,
which is a different concept this project also uses daily.

`VLAT_BackendParity` deserves its own module rather than a section inside
`VLAT_Goldens`, because it is the only test in the suite whose failure means "two
independent implementations disagree" rather than "output changed." Those are
different diagnoses and they deserve different reports.

**The golden that has to be invented, flagged because nothing else in this
document would have caught it.** `instructions_golden.vba` is the whole-corpus
behaviour-preservation witness and it exists **only on the emitter path**. IN.9
makes the emitter an export, which quietly demotes the primary golden to an
artifact of a feature most runs never touch. `VLAT_Goldens` therefore gains the
interpreter's own witness: **an effect log** — every runtime effect performed, in
order, as text, regenerated exactly as `VlaWriteGoldens` regenerates the others.
It restores the empty-diff discipline on the default path, and it turns
`VLAT_BackendParity` from a cell-by-cell comparison into a text diff, which is
the form this project already knows how to read.

`VLAT_Coverage` is where this document becomes self-enforcing. R2's layering
check, R5's string check, R6's fold check, R3's manifest check, R4's line budget,
R9's parity check over the head table, R10's backend-name check above Layer 1,
**and R11's own checks — no abbreviation outside the allow-list, no two names
differing only by punctuation or case** — all greps over `.bas` and `.vocab`
text, all runnable in one call, none needing a running Excel. A rule this file
states and nothing checks is a rule that lasts one session.

## 4. WHAT IS DELIBERATELY NOT SPLIT

The proportion test cuts both ways, and a rebuild is exactly when a project
acquires modules it does not need.

- **No `VLA_Utilities`, `VLA_Helpers`, or `VLA_Common`.** A junk drawer defeats
  R2 the day it is created — and fails R11 by construction, since a name that
  cannot claim specific contents is a name that will accept any.
- **No module per emitter arm.** `VLA_HeadTable` makes arms enumerable; that is
  the benefit sought. Thirty files would not add one.
- **No second runtime for the interpreter.** `VLAX_RuntimeHelpers` serves both
  callers. Two helper zoos with one semantics is exactly the divergence R9 exists
  to prevent, installed at the file level where no lint can reach it.
- **No `VLA_SpanishWords`, and no `lang/` folder.** LX.10's falsification test is
  twenty sentences shipped as a corpus fixture. The module is created when the
  fixture demands it, not one day earlier — though R11 has already reserved its
  name, which costs nothing.
- **No `VLA_Log` or `VLA_Trace`.** Tracing rides `VLA_Context`, where the flags
  have to live for F.5's sake anyway.
- **`VLAX_RuntimeHelpers` stays whole** despite having the most reasons to split.
  Constraint 4 outranks tidiness.

**Proportion audit, honestly.** Eight modules become twenty-two shipped plus eight
dev — call it a couple of thousand lines of headers, version constants and lints
against a sixteen-thousand-line body, on a codebase that would keep compiling if
none of it happened. The purchase is nine roadmap gates (F.1, F.4, F.6, F.11,
IN.1, IN.5, LX.2, LX.3, LX.5) moving from *held by habit* to *held by structure*,
three items (P-PRELUDE, U.14, AC.1) that stop being passes at all, and one product
capability (IN.6's no-trust install) unreachable without the Layer 1 fork. If a
reader thinks that trade is bad, the honest response is not to argue — it is §5's
field mark: *the fake microscope keeps acquiring lenses; the real one keeps
acquiring specimens.* Watch which one this topology does.

## 5. THE ORDER OF CONSTRUCTION

Bottom-up, because layers depend downward — but with the harness pulled forward,
because the builder must be the first user and the plates must exist before
anything is rubbed against them.

1. **Freeze the plates.** Goldens committed and tagged; corpus family pinned;
   baseline self-test count written down.
2. **`VLAT_Harness` + `VLAT_Goldens`**, running against the *old* pipeline. Stone
   tongs: crude, in use immediately, improved while held.
3. **Layer 0.** `VLA_Identity`, then `VLA_Messages`, then `VLA_Context`. Golden
   diff empty after each — Layer 0 is plumbing and has no licence to change an
   emitted character.
4. **`VLAT_Coverage`'s lints**, the moment Layer 0 gives them something to check.
5. **`VLA_Forms`, `VLA_Reader`, `VLA_Expander`** (prelude to file). 🔒 Golden diff
   empty at every step; the prelude move is the one place a diff is *expected*, so
   predict its exact shape first.
6. **`VLA_HeadTable`, with all seven columns declared but only the VBA column
   populated.** 🔒 **This is the fork point and it lands before the emitters are
   rewritten**, not after. A table built for one consumer acquires a second
   consumer badly; a table built for four and populated for one is the same
   afternoon's work and the whole architecture's difference.
7. **`VLA_VbaStatements` / `VLA_VbaExpressions` / `VLA_FormulaEmitter`**,
   dispatching through the table. Golden diff empty.
8. **Layer 2.** `VLAX_RuntimeHelpers` and the generated catalogue subset, verified
   in the **standalone topology** — dev workbook closed, fresh workbook, built
   add-in — because the dev workbook masks cross-project failure by construction,
   and a stateless linkage test is not a stateful sharing test.
9. **Layer 3.** `VLA_Sentences`/`VLA_Matcher` as language-neutral machinery, then
   `VLA_EnglishWords` receiving every English literal the lint finds, then
   `VLA_Phrasebooks` with the F.1 ABI check armed and the dot count published.
10. **Layer 4.** `VLA_Capabilities`, `VLA_Commands`, `VLA_ModuleInjection` (marked
    optional), `VLA_Workspace`, `VLA_Panel`, `VLA_AddinBuild`.
11. **`VLA_Interpreter` + `VLAT_BackendParity` + the effect-log golden.** By this
    point the table it dispatches through, the context it frames in, the prelude
    it implements and the helpers it calls all exist, so the interpreter is the
    smallest it will ever be. **Build it against the dot count**: every rule F.1
    converted is a form the interpreter gets for free. *Under IN.9 this module is
    the runtime*, so `VLAT_BackendParity` and `VLAT_Goldens`' effect log are part
    of its definition of done, not a follow-up — and the walking skeleton
    (IN.0.5) should already have run months earlier, on the dev rig, purely to
    price this step.
12. **`VLA_EnglishRenderer`**, once F.2 has landed and forms are the currency.
13. **Split the harness** into its final `VLAT_` shape and hand F.11's pure half
    its own entry point.

Gates, in the roadmap's notation:
🔒 **Layer 0 before Layer 1** — a fold or raise site retrofitted into a finished
emitter is the retrofit this document exists to avoid.
🔒 **`VLA_HeadTable` before the emitters** — see step 6. This gate did not exist
in the first draft of this file, and it is the most expensive one to get wrong.
🔒 **`VLA_Forms` before any English work** — F.2 is the difference between a
sibling language layer and a second string-concatenator.
🔒 **The lints before Layer 3** — Layer 3's correctness claim *is* "no English
literals below `VLA_EnglishWords`," and a claim nothing checks is a mood.

## 6. THE BOOTSTRAP: HOW TO REWRITE WITHOUT STOPPING

The first tongs are made badly, with the old tools, while the old tools are still
holding the work.

- **New module lands beside old.** The old module's procedures become one-line
  delegations. Both compile; the project never has a broken intermediate state;
  `git restore .` remains one command away.
- **One module per pass, one pass per commit**, golden diff every time. An empty
  diff witnesses behaviour preservation. A non-empty diff is a contract change and
  says so in the commit message.
- **The old module is deleted only after its delegations are unused** — its own
  commit, so a bisect can find it.
- **Predict before running.** Each pass states the golden shapes it expects
  *before* the diff is looked at.
- **Renames ride the delegation, never a separate pass.** A module that changes
  name and contents in one commit is two changes wearing one diff; the old name
  delegates until the new module is proven, then dies in its own commit.

Slower than a clean-room rewrite, and the only version with a rollback story. It
is also the only version that survives the standing override: **a real user's
breakage outranks any roadmap line**, and a project mid-clean-room-rewrite cannot
ship a fix.

## 7. THE CASE AGAINST THIS DOCUMENT

A philosophy that cannot lose is a mood with citations, so:

**Rewrites are the industry's most reliable way to lose a year.** The second
system is where hard-won behaviour goes to be re-derived, badly, by people who
remember the design and not the incidents. This codebase's incidents are
documented — a Variant that cannot ride into a typed `ByRef` parameter, an
`ObjPtr` key that is recycled memory, a ribbon that vanishes on an unescaped
ampersand, `Optional` defaults that must be constant expressions, module removal
that is deferred and mints `Name1` duplicates. A rewrite that has not read
`LESSONS.md` end to end will reintroduce them in order.

**The roadmap still does not ask for a rewrite.** It asks for splits,
chokepoints, one doctrine, and now one fork. All are reachable incrementally, and
the incremental path has the better recorded odds. **This document is best read as
the target the incremental path is aiming at** — the shape the modules should
converge on, pass by pass — and only secondarily as instructions for starting
over. That reading matters *more* after the interpreter, not less: the head table is a
one-afternoon change to a live codebase and a three-month change to a rewritten
one that does not exist yet.

**Two backends is a real, permanent tax.** Every core form becomes two
implementations, R9 makes the obligation explicit and enforced, and the honest
arithmetic is that the grammar's marginal cost per form rises. The counter is that
it rises *predictably and visibly*, priced into one table, rather than arriving as
a rewrite the day a customer's IT department says no. But anyone who tells you the
second backend is free has not written the second backend.

**And the demotion of injection rests on a market reading, not a measurement.**
IN.9's case is that enterprises block VBProject trust and quarantine emailed
`.xlsm` files while small unmanaged shops want exactly that file in exactly that
email. That is a plausible reading of two markets neither document has met.
**PI.7 is one question of one real organization and it can falsify the whole
thing** — if the pilot grants trust without ceremony *and* mails their SOP to
four departments, injection-as-default was right and this pass was a confident
error. The mitigation is that IN.9 costs nothing to reverse *at this stage*: both
backends exist in the plan, R9 keeps them honest, and which one is default is a
line in `VLA_Capabilities`. That reversibility is the only reason it was safe to
decide early, and it expires the moment a user's habits form around either one.

**And the renaming pass has its own failure mode.** Nineteen renames is nineteen
chances to break a reader's muscle memory, and a name is only worth changing while
the module it names is being rewritten anyway. Appendix D exists so the sweep is a
one-time, auditable event with reasons attached rather than a standing licence to
rename things; **R11 governs new names and modules under rebuild, not a Saturday
afternoon in the existing codebase.**

**Metametalisp schedules the work; it does not choose the work.** A topology
document is C-activity, and C-activity is warm. The test is traffic: is the new
structure being leaned on by someone shipping grammar rules, this month, and is
that someone the person who wrote it? If the answer is no for two sessions
running, the correct response is to close this file and run PI.1.
